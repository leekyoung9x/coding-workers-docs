Quy tắc:
- User gọi tên nào → dùng đúng worker + lệnh + combo đó. KHÔNG thay muse cho mini hay ngược lại.
- Mặc định ưu tiên mini worker số lượng lớn (bulk, song song); muse chỉ khi user gọi đích danh `muse-code` hoặc khi router mini (api.ai-box.vn qua 9Router 127.0.0.1:20127) chết kéo dài VÀ user đã duyệt fallback — router timeout thoáng qua thì giữ mini, retry, không tự ý chuyển.
- Nghi ngờ thì hỏi lại user trước khi spawn, không tự đoán.
- `thtung-paid` là COMBO CỦA MINI (DeepSeek), không phải model của muse.
- Tên worker là quyết định ROUTING (chọn lệnh), KHÔNG BAO GIỜ là tham số effort: `run_muse_worker.sh` chỉ nhận `none|minimal|low|medium|high|xhigh|max|ultra`. Truyền tên worker vào vị trí effort là lỗi cú pháp, worker không chạy.
- Mini key: KHÔNG dùng `mini-extra config set` (nó bọc value trong nháy đơn, mini gửi cả dấu nháy đi gây 401). Ghi file `~/.config/mini-swe-agent/.env` không nháy, hoặc export thẳng trong launcher (`OPENAI_API_KEY`/`LITELLM_API_KEY` + base `http://127.0.0.1:20127/v1` chung với Hermes).
- DeepSeek reasoning (mini) TẮT mặc định: 9Router combo `thtung-paid` báo `thinkingCanDisable: true` nên không gửi effort = chạy không reasoning. Bật max (`high`) bằng config override 2 lớp: `-c <mini.yaml> -c model.model_kwargs.reasoning_effort=high` — lớp đầu BẮT BUỘC (một `-c` đơn lẻ bỏ qua default config gây lỗi thiếu `system_template`/`instance_template`). Lấy `<mini.yaml>` động bằng đúng toolchain sẽ chạy worker (`/root/.hermes/bin/uvx --from mini-swe-agent python -c "import minisweagent, os; print(os.path.join(os.path.dirname(minisweagent.__file__), 'config', 'mini.yaml'))"`), KHÔNG hardcode `/root/.cache/uv/archive-v0/...` vì uv GC/update xóa archive cũ khiến path chết (cả symlink `~/.local/bin/mini` cũng có thể trỏ vào archive đã mất — khi đó chạy worker qua `uvx --from mini-swe-agent mini`). Model phải gọi qua combo trần (`-m thtung-paid`), KHÔNG qua prefix `openai/` với key thường (upstream 400 `No active credentials for provider: openai`). Các cách nói `effect/mạnh nhất/cao nhất/xhigh` cho mini đều tính là yêu cầu rõ — bật reasoning high. Không có các từ đó thì giữ tắt — tốn token reasoning mỗi turn.
- Watchdog treo: process còn sống + CPU time vẫn tăng nhưng log không thêm dòng nào sau ~10 phút = model kẹt suy nghĩ, không hành động. Kill rồi giao lại brief chia nhỏ (tool trước, render sau) thay vì đợi tiếp.
- Brief bắt chứng minh bằng 1 node mẫu khiến worker dừng sau mẫu và sót node khác. Bắt tool TỰ QUÉT full cây (không lấy mẫu, không gọi tay từng node) + test thêm node giả để khóa hành vi.
- Worker báo xong là nghiệm thu + báo user ngay trong cùng lượt (log, ảnh, số đo) — không đợi user hỏi mới đi kiểm.
- Brief số liệu Figma cho worker: KHÔNG lấy từ output MCP rút gọn (`get_design_context` gộp gradient thành 1 màu solid, `get_metadata` bỏ hẳn strokes/fills). Lấy `type` + stops thật qua REST nodes API trước khi ghi số vào brief — số rút gọn khiến worker vẽ sai rồi đổ lỗi vòng quanh.
- Tách worker: 1 brief = 1 worker riêng + 1 cron watchdog riêng (`watch-<TÊN-BRIEF>`), không gộp nhiều brief vào 1 worker/cron. Spawn worker và tạo cron là MỘT bước nguyên tử trong cùng lượt — tạo cron ngay khi spawn, không đợi user nhắc. Tạo cron bằng `hermes cron create --model <m> --provider <p>` CLI, KHÔNG dùng cronjob_manage tool vì schema của nó không có trường model/provider nên job ra đời đã thiếu provider và fail. Tạo trước rồi edit thêm sau khiến job chạy config cũ và fail thiếu provider. Tool `update` từ chối bổ sung model/provider sau tạo (`No updates provided`) — lỡ tạo thiếu thì xóa job và tạo lại bằng CLI, không edit. Schedule có dấu cách phải quote thành 1 arg (`"every 5m"`) — để trần shell tách làm đôi và CLI báo `unrecognized arguments`. Đặt tên `watch-<TÊN-BRIEF>`, worker xong hoặc treo là báo 1 lần rồi xóa cron.
- Tự nghiệm thu bằng probe độc lập TRƯỚC khi báo user test (curl header, browser load, login tới scene) — báo HTTP 200 mà không check nội dung là chưa nghiệm thu.
- Output md của worker (REPORT_*, brief) CẤM để ở root workspace (`/poki/*.md`): REPORT → `docs/reports/`, brief → `briefs/` — root chỉ giữ file quy ước tool (AGENTS.md/CLAUDE.md/README.md).
- Brief phải liệt kê MỌI nguồn input kể cả file Drive zip (`raw.zip` chứa `raw/overlay/`) — worker chỉ check local sẽ báo thiếu oan.
- Brief kết thúc bằng commit: CẤM `git add -A` / `git add .`, bắt `git add` từng path trong whitelist; lead tự kiểm `git show --stat HEAD` trước khi nhận.
- Repo con / thư mục bị gitignore trong workspace: `git status` ở root KHÔNG thấy sửa đổi nằm trong repo lồng nhau (root ignore nhưng dir con là repo riêng có remote). Trước khi viết brief: chạy `git check-ignore -v <dir>` + `git -C <dir> status --short` để biết code thật nằm repo nào; whitelist + lệnh commit/push trong brief phải ghi rõ repo (cd đúng dir); lead kiểm `git show --stat HEAD` cũng chạy trong repo đó. Không bao giờ kết luận "worker không sửa gì" chỉ từ root status.
- Mini tool timeout ~30s/lệnh: CẤM lệnh foreground lâu trong brief mini (`dotnet test`, `timeout 900 ...`, build lớn chạy trực tiếp) — tool 30s cắt lệnh, để lại tiến trình nền mồ côi + DB test dở dang. Bắt pattern nền + poll: `nohup <lệnh> > log 2>&1 &` rồi poll log từng chặng, mỗi poll là một lệnh ngắn.
- Brief finisher thay thế brief bị kill: xóa watch-cron cũ (`hermes cron remove <id>`) rồi tạo cron mới theo tên brief mới trong cùng lượt — hai watchdog cùng báo chéo gây nhiễu.
